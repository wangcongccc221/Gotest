# 鸿蒙 ArkTS 与 Go 后端联调培训代码版设计

## 目标

把现有 10 页架构型 PPT 扩展为一套能够支撑约 40 分钟讲解的代码版培训材料。听众应能沿着一次“等级配置保存”操作，从 ArkTS 页面追踪到 Go、TCP、FSM 回读，再回到前端状态更新，并能用同一条证据链定位数据不更新的问题。

## 受众与边界

- 听众熟悉项目，具有约 5 年以上 Qt、C# 或其他客户端开发经验。
- 听众不要求掌握 ArkTS 或 Go 语法基础。
- 培训重点是技术选型、模块边界、调用路径、状态语义和联调方法。
- 不修改任何 ArkTS、C++ 或 Go 业务代码。
- 所有代码片段来自当前工作区真实代码，并标明文件和行号。

## PPT 结构

代码版约 16 页，继续使用当前工业技术风格与 16:9 版式。

### 保留的概念主线

1. 主题与培训目标。
2. 两个独立 HarmonyOS 应用。
3. 系统边界与完整数据链路。
4. 生命周期和启动顺序。
5. HTTP 与 WebSocket 的职责分工。
6. 四种成功语义。
7. 六层联调排障法。
8. 方案的优势与代价。
9. 讨论与总结。

### 新增的 6 个代码主题

1. **两个应用如何启动**
   - Go 宿主 `EntryAbility.startNativeServices`。
   - 前端 `EntryAbility.onCreate`。
   - 强调后端先监听 18080，前端再连接和订阅。

2. **前端 WebSocket 如何建立连接**
   - `HarmonyWebSocketClient.start/connect`。
   - 连接成功后请求 `StGlobal`、统计和主页数据。
   - 展示本机地址和重连周期。

3. **等级页面如何发起保存**
   - `LevelContent.handleSaveData` 中的数据构造与乐观更新。
   - `sendGradeInfoCommand` 的 `requestId` 和保存语义。
   - 强调页面返回不等于设备已应用。

4. **Go 如何接收并下发等级命令**
   - WebSocket 命令分发。
   - `SendGradeInfoData` 的校验、合并、编码和目标解析。
   - TCP 1279 下发。

5. **Go 如何接收设备回读**
   - TCP 1128 服务接收 SYNC 帧。
   - `cmdFSMConfig` 解析 `StGlobal`。
   - 缓存等级数据并发布 `stglobal` WebSocket topic。

6. **前端如何把回读变成 UI 状态**
   - WebSocket `stglobal` 分支。
   - 不完整 `Grade` 的丢弃和重请求。
   - `GlobalDataInterface` 标记 device echo ready。
   - `UIDataSync` 驱动 `AppStorage` 与页面刷新。

## 代码页版式

- 每页只展示 10～20 行关键代码，不粘贴完整文件。
- 代码字号不低于 16pt，标题不低于 35pt。
- 文件路径和当前行号置于代码块上方。
- 使用青色标出入口和调用，橙色标出设备交互、回读或风险分支。
- 每页只回答一个问题，并在右侧或下方给出 2～3 个讲解结论。
- 详细上下文放在代码讲义和演讲者备注中，避免 PPT 变成代码墙。

## 代码讲义结构

每个主题统一包含：

1. 这一段代码解决什么问题。
2. 完整调用路径。
3. 精选真实代码片段。
4. 关键变量与协议字段。
5. 讲解时应该强调什么。
6. 联调时应该观察哪些日志。
7. 常见误判与下一步检查。

讲义末尾提供：

- 前后端文件索引。
- 40 分钟讲解时间分配。
- 现场演示步骤。
- 一张从 `requestId` 到 `StGlobal.Grade` 的证据链检查表。

## 时间安排

- 背景、架构和生命周期：8 分钟。
- HTTP/WebSocket 与启动代码：6 分钟。
- 等级保存完整代码链：16 分钟。
- 成功语义与六层排障：7 分钟。
- 权衡、讨论和总结：3 分钟。

合计约 40 分钟。

## 验证

- PPT 必须能够在 PowerPoint/WPS 中打开，包含约 16 页和对应演讲者备注。
- 所有代码路径、符号名和行号必须与当前磁盘代码一致。
- 每张代码页逐页渲染检查，不能出现代码截断、文字溢出或意外重叠。
- 代码讲义不得包含占位符、伪代码或与实际调用链矛盾的说明。
- 原始 PPT 保留不覆盖。
