# 一条数据的旅程：30 分钟培训讲稿

## 先记住这一句话

> 前端用 JSON 表达“我要什么”；Go 把请求翻译成 FSM 能识别的 SYNC 指令；FSM 通过新的 1128 连接把二进制数据推回来；Go 解析并广播，前端再按数据类别字段映射到状态和页面。

全程围绕这一句话展开。建议讲 26 分钟，最后留 4 分钟提问。

## 第 1 页：一条数据的旅程（1 分钟）

可以直接说：

> 今天不按前端、后端、FSM 分开讲。我们只跟一条数据走一遍：从 WebSocket 连接，到前端发请求，再到 FSM 回包，最后看见页面变化。

提醒听众：先记方向和边界，后面再看代码细节。

## 第 2 页：三个角色，一条链路（2 分钟）

可以直接说：

> ArkTS 前端只处理 WebSocket JSON 和页面状态；FSM 是设备侧控制程序，只认识 CTCP 二进制协议；Go 站在中间，负责协议翻译、解析、缓存和广播。

第一次出现术语时解释：

- `FSM`：设备侧控制程序。
- `SYNC`：CTCP 固定帧头。
- `topic`：WebSocket 数据帧中的数据类别字段。

不要把 `topic` 讲成客户端订阅机制。当前 hub 会把数据帧广播给全部已连接客户端。

## 第 3 页：完整链路（3 分钟）

从左上按箭头讲到右下，再沿绿色箭头回到左下：

> 请求向右走：WebSocket open、JSON 请求、Go 路由、DISPLAY_ON。返回向左走：FSM 新建连接到 1128、Go 读取解析、WebSocket 广播、前端映射显示。

必须强调：

> FSM 返回不是原 1279 连接里的函数 return，而是另一条 TCP 连接。

## 第 4 页：连接成功只代表通道建立（2 分钟）

对应代码：

`E:/new/my_harmony/entry/src/main/ets/utils/network/HarmonyWebSocketClient.ets`

可以直接说：

> open 回调只证明 WebSocket 通道可用了，不代表业务数据已经返回。当前代码不等待后端的 ready 帧，而是在 open 回调里马上发首轮请求。

当前代码会发 6 条消息：

- 4 条 `requestStGlobal`，FSM ID 分别为 `0x0100`、`0x0200`、`0x0300`、`0x0400`。
- 1 条 `requestHomeStats`。
- 1 条 `requestStatistics`。

如果现场只接一个 FSM，概念上可以只请求一个；但培训讲当前代码时，要如实说这里循环了 4 次。

## 第 5 页：前端发的是 JSON（2 分钟）

可以直接说：

> 前端不知道 1279、SYNC 和 0x0019。它只发送一个业务请求，例如 `{"type":"requestStGlobal","fsmId":256}`。256 就是十六进制的 `0x0100`，表示 FSM1。

三类请求的区别：

- `requestStGlobal`：要求指定 FSM 回传配置，后续会转成 `DISPLAY_ON`。
- `requestHomeStats`：让 Go 尝试立即推当前聚合缓存；没有统计缓存时可能没有数据帧。
- `requestStatistics`：让 Go 尝试立即推当前统计缓存；它不向 FSM 发新指令。

## 第 6 页：Go 路由和 handleRequestStGlobal（4 分钟）

这是最容易讲混的一页。先把代码分成上下两块：

```text
上半：5 个 sendLatest...  -> 回放 Go 的本地缓存
下半：go func()            -> 异步向 FSM 发 DISPLAY_ON
```

可以直接说：

> 每收到一条 requestStGlobal，只进入一次 handler。handler 先把出口名称、出口屏、附加文字等本地缓存直接发给这个前端，然后再启动一个 goroutine 访问指定 FSM。

解释 `go func() { ... }()`：

> 它不代表自动多发几次，只代表这一次网络请求在后台执行。这样 FSM 连接慢或失败时，不会卡住 WebSocket 的读循环。

当前 open 回调发了 4 条 `requestStGlobal`，因此这个 handler 会被调用 4 次，每次对应一个 FSM ID，也会各尝试发送一次 `DISPLAY_ON`。

## 第 7 页：JSON 翻译成 DISPLAY_ON（3 分钟）

可以直接说：

> Go 连接指定 FSM 的 1279 端口，发送一个 16 字节小端头。这条指令没有 payload。

16 字节不是“SYNC + FSMID + 指令”三段，而是四段：

```text
4 字节 SYNC
4 字节 srcId  = 0x1000       // HC
4 字节 destId = 0x0100       // 例如 FSM1
4 字节 cmd    = 0x0019       // DISPLAY_ON
```

发完后 Go 关闭这条 1279 连接，不在这里等待数据。

对应代码顺序：

```text
RequestStGlobalFromFSM
  -> StartCTCPClient
  -> SyncRequest
  -> SendCMD.Bytes
```

## 第 8 页：FSM 从 1128 返回（3 分钟）

可以直接说：

> FSM 收到 DISPLAY_ON 后，另建 TCP 连接到 Go 的 1128。Go 按三段读取：4 字节 SYNC、12 字节命令头、最后是 payload。

主案例的 `0x1000` 和 `0x1001` 没有长度前缀，payload 使用 `read-until-idle` 收束：读到 EOF，或 500ms 没有新字节就结束。

返回帧可以这样记：

```text
SYNC + srcId + destId + cmd + payload
```

此时 `payload` 才是真正的设备数据体。

## 第 9 页：配置立即转发，统计先缓存（3 分钟）

按两个命令讲：

> `cmd=0x1000` 是配置。Go 把 payload 解析为 `StGlobal`，转成 JSON 后立即广播。`cmd=0x1001` 是统计。Go 把 payload 解析为 `StStatistics`，先放进每个子系统的最新快照缓存。

解释 `ParseData`：

> 它先检查 payload 是否达到 Go 结构体大小，再按内存布局读取。因此 Go 的结构体布局必须和 FSM 发来的二进制布局一致。

缓存只是节流点，不是另一套业务数据源。

## 第 10 页：每秒快照并广播（2 分钟）

可以直接说：

> 后端定时器通常每 1 秒读取最新统计快照；`requestStatistics` 也可以立即触发一次。统计超过 2.5 秒未更新时，显示速度会归零。

Go 封装的数据帧是：

```json
{
  "type": "data",
  "topic": "statistics",
  "data": {},
  "at": 0
}
```

hub 遍历所有已连接客户端发送同一帧。`topic` 只标识数据类别，前端收到后自行分流。

## 第 11 页：前端分流、映射、显示（3 分钟）

先解释“映射”：

> 映射就是把 Go JSON 字段转成前端已有的结构体或状态键，而不是简单把字符串原样显示。

三条状态路径要分开讲：

- `stglobal`：映射后更新设备运行时配置。
- `statistics`：`mapStStatisticsJsonToStruct` 后写入 `GlobalDataInterface`。
- `homestats`：写入首页 KPI 的 `AppStorage` 键，页面通过 `@StorageLink` 自动刷新。

不要笼统说所有数据都经过 AppStorage。

## 第 12 页：八个节点排查（2 分钟）

可以直接说：

> 数据不显示时，不要直接改页面，也不要直接说 FSM 没发。先确认上一节点有没有输出，再看下一节点有没有收到输入。

排查顺序：

1. WebSocket 是否 open。
2. 前端 `sendText` 是否成功。
3. Go 是否进入 `handleIncoming`。
4. 是否向 FSM:1279 发出 `DISPLAY_ON`。
5. FSM 是否重新连接 Go:1128。
6. Go 是否识别 `0x1000` 或 `0x1001` 并解析成功。
7. hub 是否广播 `type/topic/data` 帧。
8. 前端是否进入对应 handler 并更新状态。

## 最容易讲错的 5 句话

不要说：`前端只发一次 requestStGlobal。`

正确说：当前 open 回调循环 4 个 FSM，所以首轮发 4 条；每条对应一个 FSM。

不要说：`后端发 SYNC + FSMID + 指令。`

正确说：完整 16 字节是 `SYNC + srcId + destId + cmd`。

不要说：`DISPLAY_ON 调用后同步返回数据。`

正确说：1279 指令连接发完关闭；FSM 另连 1128 推送数据。

不要说：`topic 是订阅。`

正确说：topic 是数据类别字段；hub 广播给全部连接，前端按字段分流。

不要说：`所有返回都写 AppStorage。`

正确说：stglobal、statistics、homeStats 分别进入运行时配置、GlobalDataInterface、AppStorage/UI 绑定。
